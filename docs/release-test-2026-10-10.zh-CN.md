# EchoCode 发布候选版功能验收

日期：2026-10-10。平台：Windows x64。版本基线：0.3.20 r4，修复产物为 r5 发布候选测试包。

本次按现有源码与公开入口整理功能范围，结合 Go 回归、竞争检测、浏览器界面测试、真实 Wails 宿主、真实浏览器和 DeepSeek 模型验收。测试不发布 Release、不提交代码，不修改用户现有供应商、项目或会话。模型测试使用此前授权的中转，密钥只从对应系统凭据条目读入测试进程。

发现并修复四类影响稳定性或数据安全的问题：子代理结果的数据竞争、插件安装/卸载的保存失败回滚、插件办公文件无法正确回退，以及 Windows junction 路径越界。修复后的专项回归、全量检查和 Windows 生产构建通过，可以进入本文已覆盖范围内的 Windows 候选版验收。

## 修复与证据

### 子代理数据竞争

首次启用完整 `-race` 后，在主 Agent 委派与父任务取消用例中复现：后台工作者读取 `parts[index]` 的同时，宿主 `applyToolResultPolicy` 裁剪同一返回切片。现在在启动工作者时传入独立快照，返回结果的修改不再影响后台任务。相关用例重复三轮通过，最终完整竞争检测通过。

### 插件生命周期回滚

安装时，运行设置改为持久化成功后才应用到内存；保存失败撤销新安装。卸载时先将包放入同卷暂存目录，配置提交失败便恢复文件和授权，成功后再清理。清理失败会明确报告保留位置。已验证安装失败、重试、授权生效、卸载保存失败、原工具仍可注册及最后成功卸载。未引入断电后跨文件事务日志。

### 插件文件回退

新增真实办公工作进程用例，先创建 DOCX、再替换正文，重启后回退并对比完整字节。原实现稳定失败：只登记产物，没有记录文件快照。

现在插件显式声明的输出文件由宿主记录前后内容，以 base64 保存二进制快照；创建、修改、删除都可参与回退。分支重放、损坏快照拒绝、外部修改保护一并验证。单个插件文件快照上限为 64 MiB；目录级权限以及插件未声明的其他文件副作用不在自动快照保证内。

### Windows junction 路径校验

本机缺少创建符号链接的权限，原符号链接测试会跳过。新增无需管理员权限的目录 junction 测试后，复现了工作区外文件可被当作内部路径访问的问题。

Windows 现在通过文件句柄取得实际目标路径，再判断允许范围；覆盖外部文件读取、尚未创建的文件写入、显式授权的额外目录以及悬空 junction。其他平台继续使用原符号链接解析。依据：[Microsoft GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew)。

## 自动化与复现

新增源码测试：

- `internal/agent/release_live_test.go`：付费真实上游测试，默认跳过；必须同时显式指定启用开关、供应商 ID、预期 Base URL 和模型，防止用错凭据或端点。
- `internal/agent/extension_roundtrip_test.go`：MCP 与 Skill 从配置到真实 Agent 工具回路。
- `internal/agent/plugin_lifecycle_test.go`：插件配置失败恢复。
- `internal/agent/plugin_rewind_test.go`：真实办公进程、二进制快照、重启、回退和分支重放。
- `internal/tools/binary_snapshot_test.go`、`junction_windows_test.go`：原始字节保护、损坏快照和目录连接边界。
- `scripts/Build-DesktopAcceptance.ps1` 与 `scripts/test-desktop-acceptance.cjs`：9 个真实 Wails 宿主场景。

桌面套件为测试二进制启用本机调试连接，并通过 Go overlay 隔离下载/临时目录。生产源码和发布二进制不启用该调试入口。套件真实调用 Wails 绑定，模型端点使用本机确定性 HTTP 服务；真实模型调用由独立的 DeepSeek 场景验证。新建项目、会话、审批、停止、回退、自动化、嵌入浏览器与整个应用重启均经过真实后端。

常规命令：

```powershell
go test -p 2 ./... -count=1
go test -race -p 2 ./... -count=1
go vet ./...
cd frontend
bun run check
bun run test:ui
```

真实模型命令需设置 `ECHOCODE_LIVE_ACCEPTANCE=1`、`ECHOCODE_LIVE_PROVIDER_ID`、`ECHOCODE_LIVE_BASE_URL`、`ECHOCODE_LIVE_MODEL` 后运行 `go test ./internal/agent -run TestLiveRelease -count=1`。不要在命令行传密钥。

## 环境与未覆盖项

Python 继续使用既有 Conda 测试前缀。为补齐 Windows race 检测，按 [Go 官方要求](https://go.dev/doc/articles/race_detector) 使用隔离的 [LLVM-MinGW 工具链](https://github.com/mstorsjo/llvm-mingw/releases/tag/20261006)，校验发布者 SHA-256；未解压其中的 Python/调试器组件，未修改全局 PATH、base Conda、系统代理或开发者模式。

本机 GitHub 直连存在 DNS 解析问题。临时向测试进程提供机器已有的代理后，公开仓库、下载和 D 盘流程通过。这不表示应用新增了系统代理自动配置；网络受限环境仍需给启动进程配置适用的 HTTP_PROXY/HTTPS_PROXY。

并行运行常规覆盖率测试与竞争检测时，两个已有的 5 秒进程测试出现启动超时；最终分开运行并限制包并发，未放宽超时断言或跳过这些用例。另修正了测试代码中 x/sys SID 子权限指针读取触发 checkptr 的问题，保留竞争与指针检查。

尚未实测的发布边界：Microsoft Office 原生打开、Chrome 专属路径、管理员符号链接权限、E/F 盘、macOS/Linux/ARM、官方 OpenAI/Anthropic/Gemini 账户、生产 SSH/MCP、长时间运行和正式安装升级。线上社区目录由用户确认尚未上线。不能把本报告理解为这些项目也已通过。

原始日志、覆盖率、隔离桌面数据与兼容文件样本保存在本机 `%TEMP%/echocode-release-audit-20261010`。它们不进入发布包；桌面包只包含生产程序和验收说明。
