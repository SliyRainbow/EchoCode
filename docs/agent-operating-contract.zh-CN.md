# EchoCode Agent 运行职责契约

更新时间：2026-07-29

本文档定义 EchoCode Agent 的长期边界。它是维护约束，不是普通用户请求的完整提示词，也不能被实现成一组按自然语言关键词分流的宿主规则。

## 核心原则

模型是任务的决策者，Agent 宿主是模型的受约束执行层。

模型负责理解用户目标、判断是否需要澄清、制定或更新计划、选择工具、安排工具顺序、决定是否委派子代理、分析工具结果、选择重试或替代方案，并给出最终结论。宿主不得根据“继续”“部署”“搜索”“修复”等词替模型预先选择工具、流程或答案。

宿主负责公开真实能力和当前权限，验证参数，执行已选择的工具，落实审批、路径边界、沙箱、超时、取消、密钥脱敏、产物登记、事件持久化和界面可观测性。宿主可以拒绝越权或不安全的动作，但不能把拒绝伪装成模型已经完成任务。

## 模型职责

- 先根据用户请求和已有证据决定直接回答、澄清、探索、计划或执行，不等待宿主关键词路由。
- 需要多个实质性工具动作时，在第一个动作前调用 `report_progress`；在拿到关键证据、进入等待/重试、改变失败策略时继续更新。进度只描述可核验事实、当前验证和下一步，不能泄露私有推理或敏感信息。
- 根据失败诊断实质性改变输入、前置条件、工具或验证方法。不得只变换引号、空格或等价参数来重复失败命令。
- 对本机配置、运行进程、指定网页或仓库等具体对象，优先读取真实对象。网络搜索只能用于发现线索，不能替代本机诊断、网页正文或源码证据。
- 创建、修改、下载或打开产物后，复用产物登记表提供的规范化绝对路径和验证状态，不应重新遍历整个工作区猜测刚才操作过的文件在哪里。
- 对图像、HTML、PDF、DOCX、XLSX、PPTX 和其他可视产物，只有在对应渲染和视觉检查完成后才能宣称视觉验收通过；不支持视觉的路由必须明确降级。
- 只有子任务相互独立、可并行且修改范围不重叠时才委派子代理。主 Agent 应继续进行不依赖子代理结果的工作，只在需要结果或最终综合时调用 `await_subagents`。

## 宿主职责

- 在每个工具开始、运行、等待、重试、结束、失败和取消时即时写入结构化事件；Shell 必须带命令、工作目录、stdout、stderr、退出码和耗时。工具输出默认可折叠，用户已展开的历史不能因后续输出自动收起。
- 工具回喂必须保留结构化结果和真实执行证据。工具同时返回部分结果与错误时，不得丢弃已有文件、diff、文本、网页、图像、子代理证据或文件变更；模型消息至少包含脱敏输入、工作目录、退出码、耗时、stdout、stderr 和错误摘要。
- 持久化任务运行快照、计划、团队 checkpoint、子代理状态、失败策略和产物登记。会话切换、应用重启、上下文压缩、rewind 和重新挂载同一路径项目后，恢复当前分支相关状态。
- 用任务级空闲看门狗和工具级超时保证终态。超时或停止后，迟到结果不得回写当前会话；无法推进时必须产生 `failed`、`cancelled` 或 `interrupted`，不能永久显示运行中。
- 支持长任务，不设置固定工具调用总次数。仅在检测到重复等价失败、无进展循环、取消、超时或明确的权限/资源边界时阻止继续，并把结构化原因交还模型。
- 支持的协议允许模型在一个回合批量提出多个独立工具调用；宿主必须串行化冲突写入，并在中转不兼容时只降级并行请求字段，不能顺带关闭工具能力。
- 团队任务的恢复和结束必须是显式 UI 生命周期操作。普通聊天文字不能隐式恢复、结束或重启已暂停团队任务。
- 团队审阅结果必须使用明确的机器协议字段；宿主不得从普通自然语言关键词猜测批准或驳回，也不得在汇总模型失败时伪造“团队已完成”。
- 团队任一角色失败都必须提交失败 checkpoint、已有角色证据和唯一终态。显式恢复操作不伪造用户消息，但其失败结果仍必须在切换会话和重启后进入模型上下文与历史记录。
- 父任务取消时通知全部子代理，并在 750ms 的收束宽限期后将未退出子代理与当前会话分离。迟到输出不能污染新任务或后续会话。
- 对用户提供的 SSH 登录密码只生成不透明凭据引用。模型、日志、工具参数、审批界面和最终回复都不能收到登录密码明文。读取已授权目标系统中的另一个密码或令牌时，使用专门的密钥捕获流程交给本地凭据库。

## 证据等级

1. 本地文件、进程、窗口、Git 状态和工具真实输出是本机任务的首选证据。
2. 指定网页必须通过 `read_webpage` 或受管浏览器读取真实正文；指定 GitHub URL 必须通过 `read_repository` 读取真实仓库树或文件。
3. `web_search` 只提供发现线索。模型应继续读取官方站点、官方文档或真实源仓库后再下结论。
4. 无法读取所需对象时，模型必须说明未验证部分和缺少的权限或用户操作，不能拿搜索摘要冒充完成结果。

## 状态与恢复契约

- 任务状态只允许处于 `running`、`waiting`、`retrying`、`failed`、`cancelled`、`interrupted` 或 `completed` 之一，并且只允许一个终态。
- 用户停止后，已经产生的有效文本、工具记录和文件变更应保留；只有尚未有可保留输出的原用户输入才回到输入框。
- 私有 reasoning 不是用户可见的有效输出。只有 reasoning 而没有正文、工具证据、产物或其他可核验结果时，失败或停止必须按零输出轮回滚。
- 项目解除挂载只移除侧边栏入口。重新添加同一规范化路径必须恢复原项目 ID、会话、分支、检查点、记忆、产物和稳定提示词身份。
- 产物登记表以项目、会话、分支和工具调用为归属，记录绝对路径、类型、大小、更新时间、哈希、验证状态和预览引用。

## 维护检查

任何 Agent 变更至少检查以下问题：

- 是否把宿主策略误写成自然语言关键词路由？
- 是否让模型看到完成任务所需的真实项目、会话、产物、失败和权限上下文？
- 是否有工具、审批、MCP、插件、浏览器、子代理或团队角色能卡住且没有终态？
- 是否有搜索摘要、旧缓存或 UI 占位文本被误当成模型最终答案？
- 是否在停止、会话切换、重启、重新添加项目和 rewind 后保留正确的当前分支状态？
- 是否同时覆盖工具执行、协议流、应用层任务包装和前端事件恢复？
