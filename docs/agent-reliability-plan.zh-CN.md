# EchoCode Agent 可靠性整改计划

更新时间：2026-07-29

本文档是 Agent 底层可靠性的长期执行清单。后续开发、对话压缩或任务恢复时，应先读取本文档，再根据代码和测试更新状态。不得仅因为单元测试通过就把部分实现标记为完成。

## 状态定义

- `未开始`：尚无可用实现。
- `进行中`：已有代码，但关键验收条件未满足。
- `待验证`：实现已完成，尚缺完整回归或真实环境验证。
- `已完成`：实现、回归测试和要求中的异常路径均已验证。
- `阻塞`：存在明确外部依赖，当前无法继续。

## P0-1：任务超时、快速停止与终态管理

### 已实现

- 上游模型建连超时为 45 秒。
- 上游模型流空闲超时为 2 分钟，并定期发送等待心跳。
- 收到 `finish_reason` 后即使上游不发送 `[DONE]`，也会在宽限期后结束。
- Shell 命令默认 120 秒超时，可由运行设置调整。
- 所有 Agent 工具统一经过宿主级执行看门狗；即使工具忽略 Context，也会按配置的 `toolTimeoutSeconds` 返回超时终态。
- 任务级空闲看门狗覆盖整轮模型、审批、工具、MCP、插件、子代理和团队等待，活动事件会续期，超时由 `taskIdleTimeoutSeconds` 配置。
- 运行状态统一包含 `running`、`waiting`、`retrying`、`failed`、`cancelled` 和 `completed`，前端对等待、重试和失败使用不同呈现。
- 超时或取消后的迟到工具结果和进度事件会被丢弃，不再写回当前会话状态。
- 停止操作立即取消任务 Context；2 秒内未退出时，前端收到强制 `cancelled` 终态。
- Windows Shell 子进程使用 Job Object，正常取消时终止进程树。

### 未完成

- [x] 增加任务级空闲看门狗，覆盖模型、审批、工具、MCP、插件、子代理和团队角色。
- [x] 统一状态枚举：`running`、`waiting`、`retrying`、`failed`、`cancelled`、`completed`。
- [x] 强制终态后隔离仍未退出的工具，不能继续写入当前会话或覆盖新任务状态。
- [x] 失败无法推进时持久化终态、错误、已完成结果和恢复入口。
- [x] 增加“工具忽略 Context”和“取消后迟到进度”回归测试。

### 验收标准

## P0-2：重复失败与策略切换

### 已实现

- 对工具名、归一化参数、退出码和错误类别生成等价失败签名。
- 忽略引号、反斜杠和空白差异，识别只改引号的等价失败。
- 检测相同结果循环和交替循环。
- 确定性失败发生一次后，第二次等价调用会在执行前被拦截；暂时性错误只允许一次受控等价重试。
- 失败状态只持久化参数哈希、退出码、错误类别和替代工具，不保存原始命令或凭据。
- 会话重启、切换、上下文压缩和 rewind 后恢复当前分支的失败策略状态。
- 连续忽略诊断并重复被拦截的方案会关闭本轮工具调用，要求模型改用不同策略或明确报告阻塞。
- 不再使用固定工具调用次数作为长任务终止条件。

### 未完成

- [x] 将失败指纹、策略类别和已尝试替代方案保存到会话分支状态。
- [x] 第二次等价失败前就向模型提供结构化诊断，不允许无实质变化的重试落地。
- [x] Shell 文件或 Office 操作失败后，明确推荐对应的结构化工具。
- [x] 区分暂时性错误、参数错误、权限错误、工具缺失和确定性数据错误。
- [x] 为停滞后的换工具、换协议、降级验证和最终失败增加 E2E。

## P0-6：Anthropic 新模型能力与真实上下文长度

### 已确认问题

- `claude-fable-5` 与 `claude-opus-5` 通过 Anthropic 原生协议请求时返回：`temperature is deprecated for this model`（HTTP 400）。当前请求组装仍无条件发送 `temperature`，导致模型完全不可用。
- 模型设置页将 `claude-fable-5`、`claude-opus-5` 及多个新模型统一显示为 `200000 / 协议默认`。这只是回退值，不代表该模型的官方真实上下文窗口。
- 不能仅按供应商或协议统一决定参数；同一 Anthropic 端点内，不同模型可能支持不同的采样、推理和输出参数。
- 当前 Anthropic 原生请求把全局推理档位同时映射成 `thinking.type`、`thinking.budget_tokens` 和 `output_config.effort`。不同代际模型可能分别要求手动 thinking budget、自适应 thinking、特定 effort 枚举或完全不接受其中某些字段；未经模型能力判断直接组合发送，会造成推理强度没有生效或直接 HTTP 400。
- 自定义 Anthropic 中转也不能仅凭供应商名称判断字段。必须结合规范化模型 ID、上游端点能力和明确的兼容错误决定请求体，且不能把 OpenAI 的 `reasoning_effort` 值原样套入 Anthropic 原生协议。

### 已实现

- [x] 新增 Anthropic 独立能力矩阵，区分不支持、手动 `budget_tokens` 和 adaptive thinking，并记录是否允许关闭、最大 effort、采样限制、最大输出及已确认上下文窗口。
- [x] 支持 `claude-fable-5`、`claude-mythos-5`、`claude-mythos-preview`、`claude-opus-5`、`claude-sonnet-5`、Opus 4.6-4.8、Sonnet 4.6 及旧 4.x/3.7 精确别名和八位日期版本。
- [x] Claude 5 保留真实 `xhigh` / `max`；Fable/Mythos 不再发送非法 `disabled`，Opus 5 的 `disabled + xhigh/max` 冲突会归一化为 adaptive。
- [x] 对明确废弃采样参数的模型完全省略 `temperature`；旧模型在 thinking 已关闭且仍支持采样时保留用户温度。
- [x] Claude 5 和已确认的新 4.x 使用 128K `max_tokens`；手动 thinking 预算最多占最终 `max_tokens` 的 75%，不足以容纳最小 1024 token 预算时省略 thinking，保证请求不会违反 `budget_tokens < max_tokens`。
- [x] Anthropic Models API 的 `max_input_tokens`、`max_tokens`、effort 档位和 thinking 类型会保存到模型配置，并随主 Agent、AI 团队、子代理及故障切换路由传递。
- [x] 自定义模型别名优先使用上游返回的 effort/thinking 能力；不支持当前档位时降到最近合法档位，而不是套用 OpenAI 字段。
- [x] 上下文来源优先级保持为手动值、上游元数据、精确目录、供应商默认和安全估算；未知 Anthropic 模型不再统一伪报 200K。
- [x] 后端和前端同步 Claude 精确目录，并覆盖原生 Complete/Stream JSON、日期别名、旧模型、自定义别名、模型能力持久化和未知上下文回退测试。

### 2026-07-27 兼容性学习验证

- `temperature`、`thinking` 与 `output_config/effort` 只有在 HTTP 400/422 明确声明不支持、废弃或不允许时才进入兼容路径。
- 首次请求只重试一次；EOF、超时、服务端 5xx、普通参数错误和未识别字段不触发兼容重试。
- 学习结果按供应商 ID 与模型 ID 写入 `runtime-settings.json`，并由主 Agent、AI 团队、子代理和故障切换路由带入后续请求。
- 同一运行任务还会共享内存能力缓存；工具循环、AI 团队和并行子代理无需等到下一轮或重启，就会立即省略已拒绝字段。
- 已学习字段在下一轮首个请求中直接省略，不再重复撞同一个上游错误。
- 手动 thinking 在最终请求组装阶段受实际 `max_tokens` 约束；4K 输出上限会把预算收缩到 3K，1.2K 输出上限会省略无法合法容纳的 thinking。
- 协议与 Agent 聚焦测试、TypeScript 检查均已通过；官方端点和真实中转验收仍需用户配置对应 API Key 后执行。

## P0-7：本机诊断路由与工具结果最终综合

### 已确认问题

用户要求检查本机 Claude Desktop 与 CCSwitch 的供应商/模型配置是否串用。EchoCode 实际只执行了 `web_search`，随后输出一组 CCSwitch 搜索结果，没有检查本机配置、进程环境或当前生效端点，也没有给出诊断结论。

截图中的“网络搜索已完成。以下摘要直接整理自搜索来源”不是模型最终回答，而是宿主代码在模型工具调用后返回空正文时，通过 `emptyToolCompletionContent` 和 `webSearchFallbackContent` 生成的兜底文本。当前逻辑把“有搜索来源”错误等同于“任务已完成”，因此这是 Agent 编排与终态判定问题，不能归因于模型不够聪明。

### 正确执行流程

1. 识别任务主体是“检查我的本机配置”，网络查询只是辅助，不是最终目标。
2. 先确认用户指的是 Claude Desktop、Claude Code 还是两者，并读取 CCSwitch 当前选中的供应商、它实际写入的目标配置和生效范围。
3. 在用户授权后，用结构化文件/电脑工具检查相关配置文件、环境变量、进程启动环境和客户端缓存；不得遍历整盘，也不得显示 API Key 明文。
4. 比较“空白群友”和“薄荷中转”的 Base URL、模型映射与当前运行进程实际使用值，判断是写错配置目标、旧进程未重启、环境变量覆盖，还是客户端读取了另一套配置。
5. 只有不知道 CCSwitch 配置位置或版本行为时才查网络；搜索后必须打开并读取官方文档或真实仓库页面，不能把搜索摘要当证据。
6. 最终输出已检查位置、实际生效来源、冲突项、结论和可执行修复步骤；若权限不足，应明确请求需要的本机读取权限，不能静默改成泛泛搜索。

- [x] `download_file` 和 `git_repository` 已进入主 Agent、团队实现者和实现型子代理的可变工具表；Plan 只读阶段不暴露落盘工具。
- [x] HTTP/HTTPS 下载支持工作区、额外可写目录和用户本轮明确授权的绝对路径；宿主仍以规范化路径和临时可写根执行最终权限校验。
- [x] 下载提供实时字节数、总大小、速度、取消、有限重试、重定向、最大尺寸、临时文件和原子落盘；失败、校验不符和取消都会清理不完整文件。
- [x] 支持 SHA-256、`Content-Disposition` 文件名、`error/overwrite/rename` 同名策略；响应头和真实文件头会共同识别伪装 HTML。
- [x] URL 用户信息、查询参数和短时签名不会进入审批、实时进度、Git stdout/stderr 或最终时间线；动态改名后的实时与最终记录按 `toolCallId` 合并。
- [x] 下载成功立即产生文件片段并登记会话级产物，规范化绝对路径、哈希、大小、类型和工具调用归属可在后续轮次、会话切换及重启后恢复。
- [x] 稳定 Agent 规则要求先读取厂商官网，识别系统、CPU 架构、发布通道、版本和安装包格式，再将最终 HTTP(S) 资源交给 `download_file`；搜索摘要和产品 HTML 不能冒充安装包。
- [x] 官网下载任务允许受控浏览器参与 JavaScript 页面定位；普通搜索仍不能擅自打开网页，用户明确禁止浏览器时优先服从禁止要求。
- [x] 下载与执行安装包是两个独立动作；下载成功不会隐式授权执行，后续安装仍经过运行权限和审批。
- [x] `git_repository` 使用结构化参数直接启动 Git，支持 clone/fetch/pull、浅克隆、分支、prune 和 `ff-only/rebase/merge`；不依赖 Shell 权限，clone 失败或取消会清理临时仓库。
- [x] Git 拉取实时显示命令、工作目录、stdout、stderr、退出码和耗时；前端使用可折叠 Git 命令详情卡。
- [x] clone 遇到 TLS 握手、连接重置和临时网络错误时最多重试两次，每次使用新的临时目录；认证失败、无权限和仓库不存在不会盲目重试，fetch/pull 也不会自动重复副作用。
- [x] 显式启用 `ECHOCODE_EXTERNAL_DRIVE_ACCEPTANCE=1` 后，D/E/F 三个真实盘符均在中文和空格目录完成 GitHub README 下载、EchoCode 浅克隆、`pull --ff-only` 及临时目录清理。

### 仍需人工验收

- [ ] 在发布版上选择数个真实软件官网，覆盖静态直链、JavaScript 按钮、多级跳转、厂商 CDN 和短时签名 URL，确认模型选择正确的 Windows 架构与稳定版资源。

### 验收标准

用户可以说“去这个软件官网下载适合我电脑的最新版到 D 盘”“把这个文件下载到指定目录”或“把这个仓库拉取到指定目录”。Agent 会核验来源和版本、展示实时动作并生成真实可用产物；权限、失败清理、停止和会话恢复均可验证，且不会未经确认直接运行安装包。

## 2026-07-29：Agent 职责边界与恢复复核

### 已完成

- [x] 审计用户文本解析边界：宿主没有根据“部署”“继续”“搜索”“修复”等普通关键词替模型选择执行路线；文本匹配仅保留 Skill 显式触发、SSH 凭据脱敏、本轮绝对路径授权和结构化失败分类。
- [x] 删除仓库读取、网页读取及 AI 团队汇总失败时的宿主业务答案。模型没有给出可用最终正文时必须继续综合或明确失败，不能由 Go 代码伪造任务结论。
- [x] reasoning-only 流不再视为可保留的用户可见输出。模型尚未输出正文、工具证据或产物时，失败/停止会回滚本轮并恢复输入；已有有效输出时才提交中断终态。
- [x] 成功 assistant 终态会清除旧失败或中断 checkpoint，迟到流事件不能覆盖已经完成的任务快照。
- [x] 所有 AI 团队非取消失败统一进入持久化失败出口。Planner、Implementer、Tester、Reviewer 和 Synthesizer 任一失败都会保存团队 checkpoint、计划终态、已有角色证据及 `turn_terminal`；显式“继续任务”失败在没有伪造用户消息的情况下也能在切换会话或重启后恢复。
- [x] 工具同时返回结构化结果和执行错误时，保留已有 text、file、diff、web、image、subagent、文件变更及产物引用，不再用一张普通错误卡覆盖证据。
- [x] 回喂模型的工具消息包含结构化执行元数据：工具名、调用 ID、状态、脱敏输入、工作目录、退出码、耗时、stdout、stderr 和摘要。模型可以基于真实错误改变方案。
- [x] 同一工作区的主会话与 detached session runtime 共享写入门；并行对话可以同时推理和读取，但冲突文件写入、Shell、Git、终端、MCP 与插件写操作会串行化，等待期间可快速取消。
- [x] 不设置固定工具调用总次数；40 次连续有效工具调用可以完成。仅等价失败、无进展周期、超时、取消或权限边界触发熔断。
