## 后端问题与处理

| 模块 | 确认的问题 | 处理及验证 |
| --- | --- | --- |
| 事件日志 | HEAD 保存失败后内存与日志可能提前更新；损坏 HEAD/父链被忽略 | 以 HEAD 持久化为提交点，失败截回旧日志长度；校验事件身份、父链、HEAD 与快照哈希。覆盖 Windows 截断、重试与重新打开 |
| 回复与任务状态 | 用户/助手消息保存错误被丢弃，界面可能先报完成再被历史刷新覆盖 | 保存失败传播到任务终态，保留真实内容和可展示推理；不为失败写入创建检查点，不重复追加助手终态。前端保留未保存输出并显示原因 |
| 启动恢复 | 无法读取设置、项目清单或会话记录时可能静默采用默认/临时状态 | 显示存储诊断，保留原文件，阻止在损坏存储上启动 Agent。正常缺失的新安装文件仍可初始化 |
| 运行设置与项目 | 写入失败却改变实时策略；额外可写目录在后台运行时或重启后不一致 | 先持久化再应用策略；项目清单保留提交快照并在失败时恢复；项目身份约束根路径，额外目录随项目恢复 |
| 回退/切分支 | 仅检查当前 Service，无法发现独立后台会话；目标分支独有文件的外部修改未校验 | 宿主检查同项目、重叠工作目录和额外可写目录的任务；串行化任务快照与时间线/会话切换操作，保留无关项目并行运行；重放前校验目标文件基线，冲突时恢复原文件和 HEAD |
| 自动化 | 配置保存失败留下内存变更；starting 状态可重复启动；旧循环影响重启；停止受存储错误阻断 | 配置失败回滚，启动中互斥，调度循环代次隔离；存储错误可见，任务停止继续执行。实时任务更新不覆盖前端草稿 |
| 扩展 | 修复/卸载先删除文件，元数据失败无法恢复；MCP 激活失败可能删掉旧版本 | 同卷暂存旧文件，提交失败恢复；激活回调纳入安装事务；卸载失败恢复 MCP 配置。损坏元数据禁止写入，清理失败单独诊断 |
| 扩展宿主 | 下载前的旧设置快照可能覆盖下载期间的修改；安装操作触发无关浏览器动作 | 激活时读取当前配置，仅提交和刷新 MCP，保留其他设置 |

权限、路径解析、审批和取消仍由宿主与工具层执行。检查了会话运行时的共享变更锁/资源门禁、MCP 工作区绑定、插件声明权限，以及供应商状态回写，不以提示词替代这些边界。
