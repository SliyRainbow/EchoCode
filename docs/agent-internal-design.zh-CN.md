# EchoCode Agent 内部设计

本文档面向 EchoCode 维护者，记录运行时 Agent 的内部架构和开发不变量。它不会作为完整正文注入普通模型请求；运行时只按任务加载短 Skill。

## 上下文结构

请求上下文分成稳定前缀和易变尾部：

1. 稳定前缀保存产品身份、行为边界、运行权限、推理档位、Skill 索引、MCP/工具 schema、稳定项目摘要和路由信息。
2. 易变尾部保存本轮宿主上下文、按需触发的 Skill、项目记忆、执行 checkpoint、工具摘要和输出要求。
3. 用户正文始终作为独立用户消息，紧跟宿主私有上下文，不能复制进私有区。
4. 历史私有上下文不进入压缩摘要，只保留当前轮需要的最新一份。
5. 用户输入、原始工具输出、重试错误和临时判断不得改变稳定前缀。

稳定前缀的顺序必须确定，schema 与 Skill 索引变化才允许改变其哈希。缓存命中是宿主组装责任，不应把缓存实现细节交给模型执行。

## Skill 生命周期

- Loader 扫描 bundled、local 和项目 Skills，项目同名 Skill 优先。
- 常规上下文只放名称、版本、显式触发条件、摘要和 SHA-256。
- EchoCode 的显式触发条件放在 `agents/echocode.yaml`，标准 `SKILL.md` frontmatter 只保留 `name` 和 `description`。
- `agents/echocode.yaml` 中的 `trigger` 只按分隔后的完整短语匹配，不使用名称碎片或宽泛关键词猜测。
- `activation: manual` 表示只能由完整 Skill 名称显式调用。
- 命中后按推理档位分配 Skill token 预算，不使用固定 Skill 数量上限；显式点名的 Skill 优先于自动触发项，超长正文只在预算边界内注入，并记录名称、字符数和估算 token。
- 内部开发说明放在 `docs/`；运行时 Skill 只保留当前任务真正需要的约束。

## 推理与工具循环

推理档位使用供应商实际支持的 `none/low/medium/high/xhigh/max` 映射。档位影响推理参数和上下文预算，不设置固定工具调用次数。

工具循环持续到以下任一条件成立：

- 模型给出最终答案。
- 用户取消。
- 工具或任务看门狗超时。
- 停滞检测确认重复失败且无法切换有效方案。
- 上下文、审批、沙箱或资源策略拒绝继续。

每轮工具结果必须包含结构化摘要、可恢复 parts、退出状态和必要引用。回喂模型的 tool 消息使用稳定 JSON 元数据携带工具名、调用 ID、脱敏输入、工作目录、退出码、耗时、stdout 和 stderr。工具同时返回 `result + error` 时，错误只改变终态，不得覆盖或删除已产生的 text、file、diff、web、image、subagent、`FileChange` 和产物引用。模型失败但工具已经产生有效结果时保留结果，不得重复用户消息或伪造完成。

支持协议时允许模型在同一回合提出多个独立工具调用，以减少模型往返；当前宿主仍按顺序执行普通工具，并通过独占门串行化写入、Shell、Git、终端和远程工具。同一工作区的 detached session runtime 共享该写入门，因此不同对话可以并行推理和读取，但不能并发修改同一工作区；等待写入门时必须响应取消。若兼容端点明确拒绝 `parallel_tool_calls`，只关闭该请求字段后重试，不能因此禁用完整工具能力。

## 权限与结构化工具

2026-10-10：schema 14 区分 `on-request` 的边界授权与 `always` 的每次询问；旧版保守策略迁移至 `always`。内置文件工具在工作区内直接执行，外部操作经具体路径与参数授权，授权只存在于该工具实例；宿主标记随快照保存以支持回退/重放，不回授模型访问权限。Windows 当前没有完整文件/网络隔离，命令继续额外审批。详见 [r8 权限验收](permissions-cache-review-2026-10-10.zh-CN.md)。

所有工具先经过 `SandboxPolicy`、路径校验和 `ApprovalPolicy`。宿主负责：

- 工作区与额外可写目录边界。
- 只读、工作区写入和更宽权限模式。
- 网络、Shell、破坏性操作与桌面控制开关。
- 超时、内存、CPU、进程数和 Windows Job Object。
- 用户审批、取消、迟到结果隔离和失败回滚。

模型看到的工具注册表必须反映当前有效权限。只读模式不暴露写文件、下载落盘、Git 拉取、Shell、SSH、持久终端或声明为可写的 MCP/插件工具；底层策略仍保留重复校验，不能只依赖隐藏 schema。

文本读取、枚举、搜索、写入、补丁、复制和删除使用结构化文件工具。`run_command` 用于构建、测试、编译器和真实可执行程序，并优先使用 `executable + args[]`，避免 Windows Shell 引号和编码问题。

## Plan、团队与子代理

Plan 是显式能力，不为普通请求额外增加规划调用。只读探索后生成结构化计划，批准后执行；状态通过事件持久化并在输入框上方独立显示。

固定团队角色为：

```text
planner -> implementer -> tester/reviewer -> synthesizer
```

Planner、Tester 和 Reviewer 默认只读；Implementer 执行修改；Synthesizer 只综合可核验结果。审阅反馈允许有限修订，不得形成无限角色循环。

Tester 与 Reviewer 的状态协议只接受首个非空行中的 `VERDICT: APPROVED` 或 `VERDICT: CHANGES_REQUIRED`。普通正文里的“通过”“需要修改”等词不能驱动宿主状态机。任一团队角色失败时保留已完成文件和角色证据，提交失败计划、团队 checkpoint 和 `turn_terminal`，宿主不得生成伪成功答案。显式恢复任务没有新的用户消息；恢复失败终态通过紧邻的失败团队 checkpoint 关联，在事件重建时恢复为 assistant 失败记录。

动态子代理通过 `delegate_task` 后台并发启动。主 Agent 继续处理文件范围不重叠的工作，只在需要结果或最终综合时 `await_subagents`。父任务结束前必须 join；父任务取消会停止全部子代理，单个子代理取消不影响兄弟任务。实时输出和终态进入结构化事件，侧栏只读展示。

## 上下文压缩与恢复

2026-10-10：新增绑定项目/会话的手动压缩接口，复用本地摘要引擎，保存失败恢复原视图，原始历史保持 append-only。空闲状态重算模型预算；运行中弹层使用最近一次上游报告的输入量。上下文视图持久化保留工具失败标志。工具链过长时，临时请求整理保留当前用户要求和最近完整工具对，并在发送前校验输入上限。详见 [r7 验收记录](context-tools-review-2026-10-10.zh-CN.md)。

上下文预算基于模型真实窗口，扣除输出、工具和安全预留。达到阈值时：

1. 发出压缩运行事件。
2. 保留稳定 system、当前请求、最近完整对话组以及完整 tool call/result 对。
3. 将较旧历史合并为一条压缩记忆。
4. 记录压缩前后 tokens、移除消息数和目标预算。
5. 失败时回滚本轮，不静默丢消息；私有 reasoning 不算可保留输出，只有 reasoning 的失败轮必须恢复原输入。

事件日志、checkpoint、rewind 和分支始终保留原始历史。停止后“继续”应恢复计划、产物、团队 checkpoint、中断位置和最近工具终态。

## 缓存与路由

每次响应记录 cache hit/miss、输入输出 tokens 和有效成本。命中率异常时依次检查：

- 稳定前缀或工具 schema 是否发生无意义变化。
- 是否重复注入完整 Skill 或大段原始工具输出。
- 项目摘要和路由信息是否被每轮重写。
- 推理档位切换是否错误重排无关内容。

供应商路由由宿主决定。协议能力、真实模型上下文和上游返回优先于根据模型名称猜测。

## 协议适配

协议差异保留在 `internal/protocol`。新增或修改协议至少验证：

- 认证、模型列表、上下文窗口和推理能力。
- 流式文本、工具参数累积、结束事件、EOF 和空响应。
- usage/cache 字段、限流、余额不足和兼容错误。
- 原生工具循环、失败转移和部分工具成功。
- Anthropic/Gemini/OpenAI-compatible 的供应商专属字段不会串用。

## 产物、记忆与 rewind

文件创建或修改后立即登记规范化路径、哈希、类型、工具调用、会话、分支和验证状态。后续轮次直接使用登记表，不重新遍历目录猜测位置。

插件显式声明的文件写入由宿主保存原始字节快照，`Encoding=binary` 的快照内容使用 base64，以支持办公文件和任意字节的回退；文件摘要与快照编码分开处理。单个插件文件快照上限为 64 MiB。目录范围权限或插件未声明的文件副作用不等于可完整回退。

Windows 路径边界使用句柄解析后的实际路径，覆盖 junction、符号链接与 8.3 别名；悬空重解析点必须拒绝，不能当作普通待创建目录。

项目记忆是受限摘要，不是完整历史复制。移除项目只解除挂载；同一路径重新添加必须恢复稳定项目 ID、会话、分支、产物和长期记忆。Rewind 移动当前 head，不删除旧事件，从历史消息继续形成新分支。

## 修改与验证

共享 Agent 链路变更应检查：

1. Go 类型、持久化和旧配置迁移。
2. 工具 schema、注册顺序、权限及取消路径。
3. 协议 mock、流式终态和故障转移。
4. 前端事件、加载态、失败态、空态和会话恢复。
5. Skill 触发、稳定前缀与上下文预算。
6. Plan、团队、子代理和长任务恢复。
7. 产物登记、视觉检查、rewind 和项目重新挂载。

至少运行：

```powershell
go test ./... -count=1
go vet ./...
cd frontend
bun run check
```

涉及 Wails API、浏览器原生表面、Windows 进程控制或打包时追加 `wails build -clean`。
