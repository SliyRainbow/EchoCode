## 已完成的核心闭环

当前默认执行链是：

``text
模型路由
  → 稳定上下文前缀 + MCP/Skills 索引
  → 模型窗口预算与自动压缩
  → Plan（可选）
  → 权限审批
  → 结构化工具循环
  → 流式响应
  → 用量/缓存/事件日志
  → UI 结构化渲染与可 rewind 历史
``

开发新功能时不要绕过这条链直接在前端拼“看起来能用”的状态。尤其不要把计划、工具调用或压缩事件伪装成助手文本。

## 发布前 P0 门槛

以下项目完成前，不应宣称稳定发行版：

1. **安全审计**
   - 明确展示 Windows Job Object 不等于文件系统/网络隔离。
   - 检查所有结构化工具的路径穿越、符号链接、额外可写目录和破坏性操作策略。
   - 检查 MCP/插件环境变量、HTTP headers、浏览器凭据和供应商密钥不会进入日志或普通配置。
   - 对第三方插件做恶意 Manifest、路径越界、输出炸弹、进程树逃逸和安装包审计。
2. **真实协议验证**
   - 为 DeepSeek、Anthropic、Gemini、至少一个 OpenAI 兼容供应商建立脱敏 E2E 测试矩阵。
   - 覆盖连接超时、流中断、空响应、限流、余额不足、工具调用半失败和模型列表异常。
   - 测试密钥只通过 CI secret 或本地环境注入，禁止提交。
3. **桌面发布**
   - Windows 安装、升级、卸载和旧 `runtime-settings.json`/SQLite 迁移。
   - WebView2、Edge/Chrome 不存在或 Crashpad 异常时的可恢复提示。
   - 长任务、浏览器帧刷新和终端输出的内存/帧率检查。
4. **可复现检查**
   - 前端 typecheck、前端回归测试、Go 全测、`go vet`、Wails clean build。
   - 在干净目录从 clone 到启动走一遍，不依赖开发机已有配置。

## 发布前 P1 门槛

- 把 Go 与前端模型上下文目录合并成单一生成源。
- 增加 CI：Windows 主检查、依赖锁文件检查、秘密扫描和构建产物检查。
- 完善多窗口/系统 DPI、输入法、键盘导航和屏幕阅读器测试。
- 为浏览器原生表面增加高 DPI、窗口最小化、设置页切换和输入法回归测试。
- 增加导入/导出运行设置的版本化格式，不导出明文密钥。
- 对 AI 团队增加取消、单角色超时、供应商故障转移和费用上限。
- 对持久终端增加会话恢复策略和退出时残留进程清理验证。
- 为办公产物增加 Word/Excel/PowerPoint/LibreOffice 打开验证、损坏压缩包、大文件、旧版 XLS 与跨平台 E2E 矩阵。
- 为二进制办公文件设计有大小上限的 checkpoint/rewind，完成前不得在 UI 中承诺可撤销。

## P2 方向

- Linux/macOS 的进程限制和浏览器原生表面补齐。
- 可选的真正 OS 沙箱后端（Windows AppContainer、容器或受控 helper），并在 UI 中区分“策略沙箱”和“OS 隔离”。
- 供应商模型目录的远端缓存、过期策略和人工校正记录。
- 更细的成本预算、缓存命中诊断和批量基准工具。
- 插件/Skill 市场、发布者签名、兼容版本范围与升级回滚。

## 修改一项能力的验收模板

1. 定义 Go 类型、权限边界和持久化行为。
2. 写服务层单元测试，覆盖成功、拒绝、取消和重启恢复。
3. 把事件加入统一 `ChatStreamEvent`，避免额外私有通道。
4. 同步前端类型、加载态、失败态和空态。
5. 检查稳定前缀是否被新字段或不稳定 schema 打乱。
6. 跑完整本地检查并记录平台限制。
7. 更新本文件和相关 Skill，说明“已实现”还是“仅 mock/测试验证”。

## 当前建议顺序

1. 先完成 P0 安全与真实协议矩阵。
2. 再补 CI 和单一模型上下文目录。
3. 然后做桌面性能、输入法、DPI 与浏览器稳定性。
4. 最后扩展更多供应商、插件和跨平台沙箱。

`go test` 全部通过不等于 Agent 已经在真实供应商、真实浏览器和真实用户工作区中达到发布质量；文档必须区分这三种验证层级。
